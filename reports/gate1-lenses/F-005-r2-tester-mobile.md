AC-36 (owner answer 3) makes `priority` settable by voice and the turn path runs on

renders priority today (zero matches for `priority` in `mobile/components/`,

*Not a finding if* AC-9 carried `(web, mobile)` as a bound the way AC-38 does, or §7
carried a fifth row plus an OQ recording priority-invisible-on-mobile as an accepted

**M2 — AC-2 — the mobile sub-bullet names no observable.** It states the obligation
as "a mobile tier verifies that F-001's row behaviour did not regress", which
resolves through F-003 AC-1's parity table to F-001 AC-18 — green under the current

Meanwhile the code ships the defect AC-2's governing sentence forbids:
`_shared/controller.ts:586-636` — `toggleTask`/`editTask`/`removeTask` dispatch

"indistinguishable from one that saved". *Not a finding if* AC-2's mobile sub-bullet
stated the post-state of a failed row write, or named by id the assertion that
changes. *Directive:* state the mobile post-state in one sentence and name the
assertion. "Did not regress" is not a testable claim.

**M3 — AC-26, AC-39, AC-3 — AC-39 is vacuously true on the platform it was created

refresh) is `(web)`. On mobile the shared `toggleTask` discards the response, so a

`(mobile)`, or AC-26/AC-2's mobile clause required the controller to apply returned
rows, or AC-39's mobile obligation named a fixture not depending on the phone
generating the successor itself. *Directive:* name which AC obliges the mobile client
to consume a multi-row response, and give AC-39 a positive mobile fixture.

**M4 — AC-38 — "when the app opens" is two doors on this client.** `init()` (cold
open, `_shared/controller.ts:172`) and `onForeground()` (resume,
`mobile/controller.ts:269`). This is **L-005's shape on the exact file L-005 names
in its Scope line**, and BUG-002 is one obligation installed at one of those doors.
F-003 AC-8 states the trigger set explicitly ("every foreground transition, resume
or cold open"); AC-38 does not. Consequence: reminders surface on cold open and not
on resume — or fire twice, and since `reminder_shown_at` is a *stored* fact, two
doors racing is a **write race**, not a display glitch. *Not a finding if* AC-38
enumerated the transitions, or stated the mobile obligation is cold open only.
*Directive:* enumerate the trigger set; say which door writes `reminder_shown_at` and
what happens when both race; require one structurally distinct test per door.

## MEDIUM

**M6 — AC-13, AC-44 — the zone, not the formatter.** AC-13's read rule names no
zone; AC-44 (which names zones) is `(api, web)`, no mobile.
`dueAtForCollection('today')` writes local midnight *of the writing device*, so a row
created on a laptop in UTC reads all-day there and as 07:00 on a phone in UTC+7 —
each client's test passing against its own expected value. Round-1 T6 reappearing on
the platform revision 2 added *after* T6 was written. The mobile client has no clock
seam at all. *Directive:* name the zone in AC-13; extend AC-44's one-seam-per-side
requirement to mobile explicitly.

**M7 — AC-19, AC-35 — a mobile test for AC-19 asserts nothing about AC-19.** Under
AC-35 a step is in no collection, no count, no a11y id set on the phone, so the
phone's rendering is identical whether the cascade completed the steps or did
nothing. The only mutation a mobile assertion can catch is a broken AC-35, which
AC-35's own case already catches. *Directive:* require the mobile case to be composed
— mobile tick on a parent, api read-back proving steps are `done`, mobile assertion
proving list/counts/a11y set unchanged — and say so, so nobody writes the second half
alone and reports it as AC-19 coverage.

**M8 — AC-35, AC-18, AC-19, AC-41 — the steps-only state is not constructible.**
`## Test strategy` requires the first-run-versus-empty-collection choice asserted for
"a user whose only rows are steps" (the mobile reader convergence 7 was written for:
`tasks-view.ts:111,113`, `index.ts:244`, `a11y.ts:276`, all verified). But AC-18
gives a step exactly one parent, AC-19 takes steps with the parent on delete, AC-41
restores the parent when a step is restored, and a parent that leaves the collection
is still a row in `state.tasks`. **Every path to only-steps is closed by another AC.**
*Directive:* name the construction path or drop the three raw-cardinality readers, and
say which was chosen.

**M9 — AC-39, AC-42, AC-43 — §8 names no mobile catalogue.** Each places a new
element on a *mobile* row, and the mobile id catalogue is the same 22-value contract
F-003 AC-12 fixes across `*-ios.html` and `*-android.html`, "none invented". Mobile

## Agent memory entry recorded from this return

A `(mobile)` tag added to close a coverage leak is only as good as the observable it
creates on a client that does not draw the surface the AC was written about. When
reviewing a platform tag, do not check that the behaviour reaches the platform —
check that a **mutation** of the behaviour changes something on that platform. If the
mutation leaves the client byte-identical, the tag buys a test that cannot fail.
