**Revision 5 (T-177) is an amendment taken after Gate 1 closed, not a fifth round.** The owner looked at the feature running on an iOS simulator, saw `CN-UNDONE` (*"Buy milk" is back on the list.*) docked under the top bar, and asked whether design or the implementers had got it wrong. **Neither had** — design published the top-docked region for AC-47's own reason (S3 Lists and S4 Settings slide *under* it, so a region inside the shell would be invisible on Settings) and mobile renders it at the frame; **the requirement is what changed, and only the owner can change it** (`docs/reports/owner-decision-2026-08-19-carried-notice-placement-and-timer.md`). **Amend-only held for the fourth revision running: 48 ACs before, 48 after, contiguous 1–48, nothing renumbered, deleted or added.** Four ACs are amended — **AC-47** (the region's edge is the bottom of the frame, with the one constraint that travels with it: on Talk the composer is at the bottom and the keyboard rises over it, so the region docks *above the composer* and may not occlude the app's primary input; and the family stops having one lifetime), **AC-43** (a fifth ender — the offer elapses after ten seconds), **AC-33** (2.2.1 restated in two halves) and **AC-41** (the depth bullet, which now has three ways to end the offer and an answer to what they end). **The lifetime split is by what the row carries, not by which row it is:** a row carrying a value the user typed is never withdrawn by time; a row carrying nothing the user typed goes after ten seconds. Written as a list of row ids it would be a rule the next row added to the family joins by default — written by carried content it decides that case in advance, and it already settles one the owner's own id table does not mention (`CN-SUPERSEDED` carries the user's superseded text, so it never elapses). **`carriedRows()` already builds the undo rows with `blocks: []` and `action: null`**, so the seam existed and only needed a rule on it. **The 2.2.1 edit is the one with a trap in it.** A ten-second limit on an affordance carrying an action is exactly what *Timing Adjustable* governs, and **pause-on-hover is not the answer** — revision 4 was written to remove precisely the reading that a focus-extended timer satisfies the criterion. What makes it conformant is that an **equivalent untimed path to the same outcome** exists, and for the four delete classes that path is **F-006's trash, which does not exist yet** — so the dependency is written into AC-43 as a **shipping order: the elapse on `CN-UNDO` does not ship before F-006.** The fifth class is the spec's own addition rather than the owner's: a **reorder** (AC-15) is not destructive and the trash does not cover it, so its untimed equivalent is the ordinary reorder that AC-16 and 2.1.1 already require to be operable — read across all five classes the owner's decision, which reasons about destructive actions only, would have left one class claiming AA conformance with nothing behind it. **OQ13 closes**: recovery is the trash for its retention period and the undo offer is a shortcut to it, so all three things that end the offer end a *shortcut*, not the recovery. **F-006 — *Recently deleted* — is a new feature with its own spec and its own Gate 1** (T-178); F-005 is amend-only with Gate 1 closed and does not build it. Per-edit disposition: `docs/reports/gate1-lenses/F-005-revision-5-log.md`. **What now leaves the spec as a dependency on F-006 rather than on architecture:** AC-41 still has **no read path that returns a deleted row** and nothing has ever purged one — 53 of 790 rows are already soft-deleted — so a retention rule is what turns a leak into a trash, and both are F-006's.
