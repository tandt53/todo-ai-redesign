At 1920 the answer was the line, not the layout

Set the width to 1920. Five full-width hairlines used to run across half-empty rows; delete them and the same emptiness reads as margin. A second task column was specified, built and rendered at that width before being rejected on the evidence — it produced two columns of half-empty rows and a second time rail.

The rail arrives at 1536 and not at 1440 for a measured reason: 1536 is the narrowest frame where it fits without the list getting narrower than it was one step below.

A short conversation sits on the composer

Pick Talk and a narrow width. The thread is anchored to the bottom, the way Zalo and Momo anchor one. The shipped app floats two bubbles at the ceiling with 618px of nothing under them at 1440.

The task detail is a property sheet, not a form

Open Task detail. Nobody fills this screen and submits it — it saves as you go and there is no Save button. So a property is a row showing its current value: Deadline · Fri 21 Aug · 6:00 PM. Tap it and the picker opens.

The drawing this replaces carried 10 bordered fields across 7 rows plus 3 segmented groups, with note, priority, deadline, reminder, repeat and steps still owed. Twelve boxes are now none. The name and the note show a ground when the value is empty, or you hover, or you are typing — the owner's own alternative to the boundary they replaced. The one boundary left on either is the focus ring, which is the single thing a ground cannot carry: bg.sunken on bg.base is 1.12:1. Try detail-blank and detail-typed-affordance inside the frame, and press Tab.

A date is a wheel on iOS and a calendar on Android

Pick Task detail, then iOS, then detail-deadline-pick. The sheet used to hold a browser date and time field — Chrome's calendar and clock glyphs, inside a UISheet. It is now a UIDatePicker wheel; on Android the same state is the M3 date picker and the M3 time input. Neither carries an OK button, because which of open, choose and dismiss writes the value is still a question for the spec.
