### C9 — `client.permission_state` exists everywhere except the data model

> The client contracts below already exist as declared rows in

This is drift in the direction C9 exists to catch: an entity the implementation
carries that the data model does not know about. It is unambiguous — no

warning. The fix is one table row in `data-model.md` plus correcting the F-003

## Overturned tool verdicts

### C14 — the tool read zero bytes and reported the whole catalogue missing

Invoked as the reviewer protocol specifies, with `--impl "<implemented_in>"`:

```
testid-contract: 0 honoured, 22 missing, 0 undeclared
```

Every single declared id, reported absent. Both halves of that are wrong, for
two stacked reasons:

1. **`ids_in()` skips directories.** It iterates `for f in $1` and guards with
   `[ -f "$f" ]`. F-003's `implemented_in` is
   `[src/assistant/mobile/, src/assistant/_shared/]` — two directories. The tool
   matched no files, scanned nothing, and reported the full catalogue missing
   **without warning that its input matched nothing.**
2. **The regex cannot see a helper-applied prop.** Re-running with an explicit
   recursive file list still gave `0 honoured / 22 missing`, because the
   implementation never writes a literal `testID=`. Every id is applied as a
   spread of a helper's return value:
   `{...a11yProps(A11Y_IDS.micButton, {label: 'Nhấn để nói', role: 'button'})}`.
   `a11yProps` returns `{testID: id}` (`model/a11y.ts:94`) — a colon, not an
   equals, and the value is a variable.

What settled it, per L-002 — execution observables, not source text:

- **All 22 catalogue keys are referenced in `components/`** (mechanically
  checked: `ids never referenced in components/: 0`). Spread across
  `Chrome.tsx`, `Composer.tsx`, `ConversationList.tsx`, `TaskList.tsx`,
  `VoiceSurface.tsx`.
- **The executed suite asserts the contract in both directions.**
  `src/assistant/mobile/__tests__/a11y.test.ts` parses `accessibilityIdentifier`
  out of the iOS mockup and `resource-id` out of the Android one, asserts both
  are 22 and identical, asserts they equal the web `data-testid` catalogue
  (AC-1's no-fork claim), then asserts `ALL_A11Y_IDS` has nothing missing and
  nothing invented against the mockups. This ran green this pass.
- **`expectedIds()` is not a parallel description of the UI** — `a11y.ts:33-44`
  imports its predicates (`showMic`, `showStateIndicator`, `showCancel`,
  `showOfflineBanner`, …) from `surface.ts`, the same module the components
  render from.

Verdict: **PASS**. The contract is honoured, including AC-12's negative half —
no catalogue id sits on `contentDescription`, so TalkBack speaks the message
rather than the token.

**Residual gap, stated plainly:** no test renders the React Native component
tree, so "the component applies the prop" rests on static reference (my grep)
plus the catalogue-vs-constants assertion, not on a rendered observable. The
platform doc sanctions this ("No RN component snapshot tests this phase"), and
it is the honest limit of what this tier proves. It is on the human checklist.
