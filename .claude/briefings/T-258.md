## Context

You drew the F-009 search states. State `search-filtering` in `app-shell.html` carries the query
**"bill"** and shows **4 rows, of which exactly 1 contains "bill"** — *Pay the electricity bill*.
*Send the weekly report to Hanh*, *Gọi nha sĩ đặt lịch khám răng* and *Buy milk* match nothing.

Compared with `tasks-default` (5 rows) the only thing that changed is that the **done row disappeared**.
That is `AC-7` hide-completed, a different feature. The mechanism is the CSS rule
`.app[data-search="filtering"] .row.done { display:none }` — which the Gate 1.5 dev lens had already
flagged as contradicting `AC-2`.

**`AC-2` is live filtering by title.** So the one state whose whole job is to show the list narrowing
shows a list that has not narrowed. (`search-no-results` is correct by contrast: query "meeting", 0 rows.)

Three review lenses passed this. The spec lens wrote *"AC-2: search-filtering state shows live narrowing
with query 'bill'. Covered."* — it verified the state exists, not what it contains.

## What to do

1. **Redraw `search-filtering` so the visible set is the set that matches the query.** With query "bill"
   that is one row. If one row makes a poor illustration, change the query to one that matches two or
   three rows — the requirement is that *every visible row contains the query*, not that the count is high.
2. **Remove the `display:none` on `.row.done` under `data-search="filtering"`**, or replace it with a rule
   derived from the query. A done row whose title matches the query is a match; hiding it is AC-7's job on
   a different surface, not search's.
3. **Do the same on the iOS and Android shells** if they carry the state. Check; do not assume either way.
4. Re-check `search-no-results` and any other search state against the same predicate while you are there.
