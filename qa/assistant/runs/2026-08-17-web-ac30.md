## The rule these cases were written against

BUG-004 shipped on both clients because **every existing assertion in this repo
asked whether a message was present.** A message rendered 176px below the fold
satisfies `toHaveCount(1)`, satisfies a text filter, and satisfies
`toBeVisible()` — Playwright's visibility means rendered and unhidden, not
inside the scrolled viewport. So none of these cases assert presence. They
compare rectangles, and they compute clause (a)'s `distance_from_bottom` off the
live layout.

## The failure — BUG-006

**TC-047**, `AC-30(h)`. From a scrolled-up position the user sends an ordinary
turn. Expected `distance_from_bottom ≤ 48`, no affordance, reply on screen.
Actual: `distance_from_bottom = 121`, one `1 new message` pill, reply below the
fold. **3 of 3** isolation re-runs (`_qa-foundations.md` §8 step 1), plus four
independent one-off browser probes before the case existed.

Triage: assertion error → re-read the AC → clause (h) states the postcondition
as an end state and the system does not reach it → **product bug**, layer `web`.
Frame-by-frame evidence, the reduce-motion control case, and the two suggested
fixes are in `qa/_shared/bugs/BUG-006-own-send-lands-short-of-the-bottom.md`.

Short form: the clause-(h) scroll is animated, its target is computed once from
the pre-reply content height, and a reply arriving mid-animation reads
`distance_from_bottom` off the *moving* offset — so it takes clause (c)'s branch
and the surface stops 121 units short for good. It reproduces with fast replies
(every canonical fixture row) and not with delayed ones, which is why TC-047 is
deliberately written with a canonical row: written with a slow row it would be
green over a broken behaviour.

## Script bugs fixed during triage — four, all mine

Recorded rather than quietly fixed, because two of them are the shape where a
test reports on a scenario other than the one it names.

1. **`bubbleWithText(...).toHaveCount(n)` can never exceed 1.** The helper ends
   in `.last()`. Used as a thread-builder assertion it was satisfied trivially,
   and the real bubble count was double what the loop believed.
2. **`test.use({ reducedMotion: 'reduce' })` is silently inert** against this
   project's Playwright/browser build: under it the page reports
   `matchMedia('(prefers-reduced-motion: reduce)').matches === false`. All three
   clause-(g) cases first ran in **ordinary motion while claiming to test
   reduced motion** — two failed for the wrong reason and either could as easily
   have passed for the wrong one. Fixed with `page.emulateMedia()` plus an
   assertion that the preference actually took. `test.use({ viewport })` in the
   375px case is unaffected and does work.
3. **TC-039 was parking after the arrivals it was measuring.** With 1500ms rows,
   two of the three outcomes landed while the user was still at the bottom, so
   the case recorded `[0, 0, 1]` affordances and looked like a product defect.
   The fixture delay is now 2500ms — set by this case's worst-case timing, and
   the reason is written into the harness so it is not tuned back down — and the
   park is now **asserted** before the arrivals are awaited.
4. **Waiting on a bubble total does not detect an arrival.** A turn in flight
   already occupies a bubble which the outcome then fills rather than adding to,
   so the total is identical before and after. Each arrival is now awaited by
   its own outcome text.

## Falsifiability checks — done, not assumed

`_qa-foundations.md` §5: the only honest question about a suite is whether it
would notice a broken implementation. Checked by breaking things on purpose.

| Check | Method | Result |
|---|---|---|
| TC-047 | none needed | fails against the real defect, 3/3 |
| TC-044/045/046 | ran the same cases with the preference off | 7 and 48 intermediate scroll offsets against 1 with it on — the step-count assertion separates them |
| TC-035 vs TC-036 | the same viewport helper is asserted `true` in one and `false` in the other, in one run | not a constant |
| TC-041 | DOM-only mutation: forced `white-space: nowrap`, clamp 1 | label `scrollWidth` 277 → 313 against `clientWidth` 277 — assertion flips |
| TC-038 | DOM-only mutation: gave the dock layout (`position: static`, `height: auto`) | dock 0 → 40.5px, pill top 590.5 → 598.5 against a conversation bottom of 639 → 598.5 — assertion flips |
| TC-039 | its own broken setup | reported `[0, 0, 1]` before the timing was fixed |

**TC-038's first version would not have failed**, and that is the finding worth
carrying: with the user parked at the top of the thread, a dock that takes
layout shrinks the conversation viewport from its *bottom* edge, so the message
the user is reading does not move and the box comparison stays green through a
reflow. The overlap assertion was added because the mutation exposed the gap.
Both assertions are kept; they catch different reflows.

All mutations were **DOM-only, inside the browser** — no file on disk was
modified, so L-001/L-010's restore hazard does not apply here at all.

## Harness handling (T-079 mitigation) — stated, since the briefing asks

T-079: `freshUser()` restarts `userSeq` at 1 on every process start while the
harness server, started with `reuseExistingServer`, keeps its `MemoryStore`
across runs — so run N can inherit run N−1's account and conversation. Three
things were done, and the first two are durable:

1. **Every AC-30 account carries a per-process `RUN_ID`**
   (`qaweb-{tc}-{RUN_ID}-{n}@qa.example.com`), so collision is impossible
   however long the harness has been up. The pre-existing 36 tests still use
   `freshUser()`; T-079 stays open for them and is not fixed here.
2. **The harness process was killed before each measured run**
   (`lsof -ti tcp:4460 | xargs kill -9`), so the fixture table and the store are
   both known-fresh.
3. **Every case asserts its own preconditions** — the park held, the outcome had
   not arrived yet, the conversation actually overflows, the reduce-motion
   preference actually took. Contamination that survived 1 and 2 would fail a
   precondition rather than silently changing what a case measures.

A related trap worth recording: a **surviving harness also serves the previous
run's fixture table.** The first probe of the new `qaweb ac30 *` rows returned
`no_match` — not because the rows were wrong, but because the process holding
port 4460 predated them. The symptom looked exactly like a broken scenario.

## Selector-contract note

The conversation's scroll container has no entry in the 22-testid catalogue, and
the contract forbids reaching for `.conv-scroll`. Every measurement here derives
the scroller by walking up from the conversation's published `role="log"`
(AC-19 / TC-033) to the nearest genuinely scrollable ancestor. That anchor is
semantic and survives restyling, and it fails loudly if the surface stops
scrolling at all.

**Request to design-agent:** publish `assistant-conversation-scroller` on the
scroll container in the three mockups. AC-30 makes that element a first-class
part of the contract — eight clauses are defined as measurements of it — and it
is currently the only such element reachable only by inference.
